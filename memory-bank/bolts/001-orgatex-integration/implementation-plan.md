## Implementation Plan: orgatex-integration (bolt 1 of 17)

### Objective

Create the shared project scaffold that every later bolt builds on, and the **read side of the OrgaTEX integration**: the Dummy OrgaTEX external system (training contract, own database and seed) and WeighingMS's `OrgatexPort` with its dummy adapter. After this bolt the server runs, `/ext/orgatex` serves the prototype's training scenario, and WeighingMS code can read batches, recipes and lots **only** through the port.

### Stories and requirements implemented

| Story | Requirements | What it delivers |
|-------|--------------|------------------|
| `001-project-scaffold` (enabler) | Standards: tech-stack, data-stack, coding-standards, api-conventions, system-architecture | Workspace, app factory, `/api/health`, error format, decimal quantities, lint/format/test |
| `002-dummy-orgatex-serves-batches-and-recipes` | DB-1 (read side), supports FR-2, FR-5, FR-8; A-01 | `/ext/orgatex` read endpoints, `orgatex.db`, seed data |
| `003-orgatex-port-read-operations` | IR-07, IR-09; supports FR-2, FR-5, FR-8, FR-32 | `OrgatexPort` interface + dummy adapter with error translation, timeout, logging, link status |

Out of scope for this bolt (planned elsewhere): consumption posting, batch status writes, `_sim` controls (bolt 002); the WeighingMS `/api/batches…` facade (bolt 005); any UI screen (bolt 007).

### 1. What will change

The repository goes from documents-only to a runnable TypeScript application:

1. **Tooling**: one root `package.json` (npm), TypeScript strict, ESLint (flat config, `typescript-eslint`), Prettier, Vitest, Vite + React, Drizzle Kit.
2. **Server scaffold**: Fastify app factory `buildApp(config)` used by both `main.ts` and tests; config (host `127.0.0.1`, port, station ID, environment, simulation flag); central error handler mapping `DomainError` → `{ error: { code, message, details? } }`; pino logging; `GET /api/health`.
3. **Shared**: decimal `Quantity` type and helpers (`decimal.js`); unit conversion g↔kg.
4. **Dummy OrgaTEX** (isolated module under `src/server/integrations/orgatex/dummy/`): Drizzle schema for `orgatex.db`, migration, seed loader from `data/seed/orgatex-seed.json`, read routes under `/ext/orgatex`.
5. **OrgatexPort + adapter**: TypeScript interface (WeighingMS's view) and an HTTP adapter that calls `/ext/orgatex`, maps payloads to port types, translates errors, times out after 2 s, logs every call, and tracks link status.
6. **Web shell**: minimal Vite/React page with the `ux-guide.md` design tokens loaded (dark HMI background, "WeighingMS" text) — proves the UI toolchain; no prototype screen yet.

### 4. APIs involved

**Created — Dummy OrgaTEX (training contract, not the real OrgaTEX interface):**

| Method | Path | Returns |
|--------|------|---------|
| GET | `/ext/orgatex/ping` | `{ status: "ok", at }` (link check) |
| GET | `/ext/orgatex/stations/:stationId/batches` | `{ items: Batch[], generatedAt }` |
| GET | `/ext/orgatex/batches/:batchId` | `Batch` or 404 `BATCH_NOT_FOUND` |
| GET | `/ext/orgatex/batches/:batchId/recipe` | `Recipe` (components in sequence) or 404 `BATCH_NOT_FOUND` / `RECIPE_NOT_FOUND` |
| GET | `/ext/orgatex/dyestuffs/:code/lots` | `{ items: Lot[] }` or 404 `DYESTUFF_NOT_FOUND` |

Batch: `batchId, orderRef, machineRef, fabricDesc, fabricWeight {value, unit:"kg"}, shade, componentCount, status (QUEUED|RELEASED|WEIGHING|WEIGHED), recipeId|null, releasedAt|null`.
Recipe component: `sequence, dyestuff { code, name, colourHex, ticketShortName, type }, target {value, unit}, tolerance {value, unit}, barMax {value, unit}, suggestedLot`.

**Created — WeighingMS:** `GET /api/health` → `{ status: "ok" }`.

**Created — port (in-process):** `OrgatexPort` with `listBatches(stationId)`, `getBatch(id)`, `getRecipe(id)`, `listLots(dyestuffCode)`, `getLinkStatus()` → `{ state: ONLINE|OFFLINE|UNKNOWN, lastContactAt }`.

### 6. Technical approach

- **App factory**: `buildApp({ config, orgatexPort? })` registers plugins: health, `/ext/orgatex` dummy, and (later bolts) `/api` modules. Tests build a fresh app with an in-memory Dummy OrgaTEX DB.
- **Adapter transport**: the adapter depends on a tiny `HttpClient` interface (`get(path)`). Runtime uses `fetch` against `ORGATEX_BASE_URL` (default `http://127.0.0.1:<PORT>/ext/orgatex`); tests use an `inject`-based client so no network port is needed. Unreachable-dummy tests use a client pointing at a closed port and a slow-responding stub to exercise the 2 s timeout.
- **Error translation**: dummy 404 codes → `BatchNotFoundError` / `RecipeNotFoundError` / `DyestuffNotFoundError`; network error, timeout or 5xx → `OrgatexUnavailableError` (503); malformed payload → `OrgatexProtocolError` (502).
- **Link status**: adapter records `lastContactAt` on every successful call and `OFFLINE` after a failure.
- **Logging (IR-09)**: one structured line per adapter call: `{ system: "orgatex", operation, batchId?, outcome, durationMs }`.
- **Quantities**: stored in SQLite as `TEXT` decimal strings with a unit column; never `REAL`.
- **Simulation flag**: `config.enableSimulation` (true in `development`/`test`) is created now so bolt 002 can register `_sim` routes conditionally.
- **Dev run**: `npm run dev` = `tsx watch src/server/main.ts` (port 3000) + `vite` (port 5173, proxies `/api` and `/ext` to 3000) via `concurrently`.

### Risks / notes

- **Tool versions**: latest TypeScript (7.x) is incompatible with `typescript-eslint`; pinned to 6.0.x.
- **`better-sqlite3`** is a native module; prebuilt binaries exist for Node 24 on Linux. If the install fails, fallback is Node's built-in `node:sqlite` with Drizzle's matching driver — would be recorded as a deviation.
- The Dummy OrgaTEX contract is a **training contract**; route files carry a header comment stating it is not the real OrgaTEX interface.
